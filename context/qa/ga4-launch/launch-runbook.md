## Rollback

On form/routing/security regression, duplicate/missing required analytics, wrong destination or failed acceptance, stop and use the preapproved rollback authority.

1. For an analytics-only failure, keep the reviewed website and its consent gate. Publish the pre-reviewed **measurement-paused configuration** (all ten tags paused, zero active measurement/Ads), record its assigned version and verify collection has stopped in a fresh session. Preserve all tag parameters and dependencies for diagnosis. Do not automatically reactivate version 3's legacy Ads or generic lead tracking.
2. For a form/site/security failure requiring the prior website, pause measurement as above **before restoring the recorded actual prior Netlify production deploy**, because that earlier website does not implement the newly chosen opt-in. Verify the previous form UI and intended routing after rollback. Previously loaded tabs may retain executing code; publication is not an instant recall, so log propagation and do not promise an atomic stop.
3. If the owner instead explicitly authorizes a complete return to the previous analytics behavior after reviewing its Ads/consent differences, GTM Versions → recorded prior version (currently 3) → Publish restores that preserved container. Restore the recorded GA4 history settings and any specifically changed key-event/rule setting from the baseline. Verify both mirrored history controls and fresh-session measurements. This is a separate decision from the recommended measurement-paused fallback.

Annotate the measurement interval; do not resend accepted inquiries or send another test email automatically. No bulk abandonment of the existing Default Workspace or secret changes.
